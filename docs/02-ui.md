# 02 · 控制台 UI：架构与配置

## 1. 架构

```
浏览器 ──HTTP──▶ [ wasm 组件 （wasm32-wasip2） ] ──明文 HTTP──▶ [ kube-api-proxy ] ──TLS+SA token──▶ API Server
                       │
                       └─ 编译期嵌入的前端 SPA（HTML/JS/CSS）
```

- **后端**：一个 `wasi:http/proxy` 组件。同步代码、无 async runtime、无 tokio。
  路由是手写的纯函数（十几条），JSON 形态在 `api.rs` 里收窄。
- **前端**：无框架 TypeScript + Vite，构建产物 36 KB（JS 20 KB / CSS 7 KB / HTML 1.8 KB），
  经 `include_dir!` 在**编译期**嵌进 wasm。于是组件运行时**不需要任何文件系统能力**。
- 产物大小：wasm 约 315 KB（含前端），见 `make wasm`。

数据流的一个副作用：`/api/health` 会真的去问 kube-api-proxy，所以它可以当**就绪探针**，
同时证明「组件 → 代理 → API Server」整条链路通。

## 2. API

统一信封，前端只认两种形状：

```json
{ "ok": true,  "data": ... }
{ "ok": false, "error": { "message": "...", "status": 403 } }
```

上游 k8s 的错误（含 RBAC 拒绝的具体原因）**原样透传**，不换成「请求失败」。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 自身状态 + 生效的配置来源 |
| GET | `/api/summary` | 概览聚合 |
| GET | `/api/nodes` `/api/runtimes` `/api/namespaces` | 集群视图 |
| GET | `/api/workloads?namespace=` | Deployment 列表 |
| GET | `/api/pods?namespace=&node=` | Pod 列表 |
| GET | `/api/pods/:ns/:name/logs?tail=` | 日志（上游是 text/plain，单独处理） |
| GET | `/api/events?namespace=` | 事件 |
| GET/POST | `/api/spinapps` | SpinApp 列表 / 创建 |
| GET | `/api/spinapp-executors?namespace=` | executor 列表（SpinApp 的 runtimeClassName 来自它） |
| POST | `/api/spinapps/:ns/:name/scale` | 扩缩（merge patch `spec.replicas`） |
| DELETE | `/api/spinapps/:ns/:name` | 删除 |
| GET/POST | `/api/xray/tunnels` | 隧道列表 / 创建 |
| POST | `/api/xray/tunnels/:ns/:name/scale` | 扩缩 |
| DELETE | `/api/xray/tunnels/:ns/:name` | 删除（Deployment+Service+ConfigMap） |
| GET | `/api/auth/status` | 认证状态（**匿名可用**）：是否已配置、是否已绑定凭据、是否已登录、RP ID/origin |
| POST | `/api/auth/register/begin` `/register/finish` | 首次绑定 passkey（需一次性注册码） |
| POST | `/api/auth/login/begin` `/login/finish` | 免密登录（WebAuthn 断言） |
| POST | `/api/auth/logout` | 退出（清签名 cookie） |
| GET | `/*` | 静态资源，未知路径回退 index.html；未知 `/api/*` 返回 JSON 404 |

> **门禁**：除 `/api/health` 与 `/api/auth/*` 外，所有 `/api/*` 都要求有效会话
> （HMAC 签名的 cookie）。未登录 401；会话密钥没配置则 **503 并说明缺什么**
> （失败关闭，不放行）。静态资源不鉴权 —— 登录页本身就是静态资源，数据由门禁挡。
> 登录方案与部署见 `docs/06-auth.md`。

## 3. 配置：为什么用环境变量 + 编译期默认值

`K8S_PROXY_URL`（默认 `http://kube-api-proxy.k3s-wasm.svc.cluster.local:8001`）：

1. 容器环境变量（runwasi 的 wasmtime shim 会把容器 env 通过 wasmtime 的 `.envs()` 传给 guest；
   Spin 宿主下用 `spin up --env-file` / `-e`）—— 实测有效，`/api/health` 会显示 `proxyUrlSource: env`
2. 编译期默认值。非标准命名空间可以用 `K3S_WASM_PROXY_URL=... ./scripts/build-ui.sh --import` 烘焙进去。

**没有走 Spin variable**：那会引入 `spin:*` 宿主接口导入，组件就不再是「标准 wasi:http 组件」了，
而标准性正是它两种宿主都能跑的原因。

## 4. 为什么中间放了一个 kubectl proxy

`deploy/base/kube-api-proxy.yaml` 里跑的是官方 `registry.k8s.io/kubectl` 镜像的
`kubectl proxy`。它存在的唯一原因：

> 组件的出站 TLS 由**宿主**完成，而宿主的信任根我们配置不了。
> k3s 默认给 API Server 签的是集群自签 CA，于是直连 `https://kubernetes.default.svc`
> 会握手失败，且没有可用的出口注入自定义 CA。

所以把 TLS/证书/Token 全留在组件之外，组件只讲明文 HTTP。**代价必须明确**：

- 这个 Service 在集群内是**无认证**的：谁能访问它，谁就拿到 ClusterRole `k3s-wasm-console` 的全部权限。
- 因此配套了 NetworkPolicy，只允许控制台 Pod 访问 8001 端口（k3s 自带 network policy controller，是生效的）。
- ClusterRole **故意不给 secrets 权限**：即使代理被同命名空间的 Pod 摸到，也读不到任何密钥。

不想要这个组件的话：从 `deploy/base/kustomization.yaml` 去掉它，并让组件直连 API Server
（需要宿主支持配置自定义 CA —— 目前 wasmtime shim / Spin 都不直接暴露这个能力）。

## 5. 本地开发闭环

```bash
# 方式一：mock k8s API + 真实 wasm 宿主（推荐，改前端可热更新）
python3 scripts/dev-mock-k8s-api.py --port 8001 &
cd ui/frontend && npm run dev          # Vite 会把 /api 代理到 :8080
wasmtime serve -C cache=n -S http=y -S inherit-network=y -S inherit-env=y \
    --addr 127.0.0.1:8080 ui/backend/target/wasm32-wasip2/release/k3s_wasm_ui.wasm

# 方式二：一条命令（会自己起 mock 与宿主）
./scripts/dev-serve-local.sh

# 方式三：全部断言（31 项）
make e2e
```

mock API（`scripts/dev-mock-k8s-api.py`）支持 `--no-spinapp-crd`，用来验证前端
「SpinKube 未安装」的提示路径；它也支持 chunked 请求体 —— 这点很关键，
wasi:http 的出站请求常用 chunked，mock 不认的话 POST 的 body 会静默变空。

## 6. 前端为什么不用框架

- 产物会**直接加在 wasm 体积上**（用户每次都要下载）；
- 界面复杂度用 ~200 行 DOM helper + 视图工厂就够了；
- 每个视图是一个工厂函数，于是「选中哪个 Pod」「表单里输入了什么」都是闭包变量，
  不需要全局状态管理。

轮询策略：只读视图 `autoRefresh = true`（整体重渲染安全）；带表单的视图 `false`，
轮询只重画列表部分，避免把用户正在输入的框清空。
